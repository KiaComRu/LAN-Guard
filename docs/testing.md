# Проверка LAN Guard

Автоматические тесты запускаются командой `dotnet test LanGuard.slnx`. Они проверяют синтетические наблюдения детектора, SQLite-миграции, вход, CSRF, выдачу и однократное использование токена, ротацию секрета, идемпотентность отчётов и отображение неполного покрытия. Для панели `npm run build` проверяет TypeScript и собирает файлы для веб-сервера.

## Проверка на тестовом Windows ПК

1. Выполните `LanGuard.Agent.exe --inventory-only`. Проверьте список источников и причины недоступности.
2. Поднимите сервер с доверенным TLS-сертификатом и установите службу по инструкции. Проверьте, что ПК появляется в списке и получает первую отметку проверки.
3. Сравните доказательства для разрешённого тестового экземпляра ПО с записями реестра, процессами и службами стенда.
4. Остановите сервер, дождитесь следующей проверки и перезапустите службу. Затем запустите сервер и проверьте, что накопленные отчёты обработались без дублей.
5. Остановите службу на три минуты и обновите панель. Проверьте отметку «Нет связи» и дату последнего heartbeat.

Для проверки работающего продукта в автоматическом тесте можно использовать фикстуру наблюдений из `tests/fixtures/demo.json`. Адреса демо относятся к документационному диапазону TEST-NET-1.
