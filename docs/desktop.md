# LAN Guard для Windows

Запустите `LAN-Guard-Setup-x64.exe` на Windows 10/11 x64 и откройте **LAN Guard** в меню «Пуск». Приложение устанавливается для текущего пользователя и содержит собственную среду .NET.

1. Выберите сетевой адаптер, подключённый к проверяемой локальной сети.
2. Проверьте диапазон IPv4 и нажмите **Сканировать**. Приложение автоматически подставляет подсеть адаптера. Для подсетей крупнее /22 задавайте отдельные диапазоны в пределах того же сегмента.
3. Выберите устройство, чтобы увидеть подробности. Фильтр в верхней части окна оставляет устройства с открытыми портами или с совпадениями по реестру в зависимости от режима.

Колонка **Компьютер** показывает имя из обратного DNS или ответа NetBIOS. Когда эти источники не дали результата, приложение пробует mDNS и LLMNR в выбранном сегменте. В режиме проверки реестра предпочтение отдаётся имени из реестра. Источник имени виден в подробностях устройства. [mDNS](https://www.rfc-editor.org/rfc/rfc6762.html) · [LLMNR](https://www.rfc-editor.org/rfc/rfc4795.html)

Если имя не удалось получить по сети, нажмите **Загрузить имена из CSV…** и выберите список активных аренд DHCP с роутера или DHCP-сервера. Подойдут заголовки `IPAddress,HostName,ClientId` из Windows DHCP Server или простой файл UTF-8 в таком формате. [Windows DHCP Server](https://learn.microsoft.com/powershell/module/dhcpserver/get-dhcpserverv4lease)

```csv
ip,name,mac
192.0.2.30,OFFICE-30,02:00:00:00:00:30
192.0.2.32,OFFICE-32,
```

Достаточно указать имя и IP- или MAC-адрес. При наличии MAC предпочтение отдаётся совпадению по MAC. Имена из файла дополняют текущие результаты и используются при следующих проверках до закрытия приложения. Если устройство обнаружено, а совпадения по имени нет, в таблице остаются IP-адрес и отметка **Не определено**.

## Карточка устройства

Нажмите на любой IP-адрес в таблице. Карточка сразу показывает данные основного сканирования и запускает дополнительный сбор для выбранного устройства. Это работает в обоих режимах, в том числе для строк без признаков удалённого доступа. Закрытие карточки отменяет текущий сбор.

- **Порты** — открытые порты из списка распространённых TCP-служб, включая SMB, HTTP(S), SSH и печать. Подпись службы определяется по номеру порта.
- **Сетевые адаптеры** — описание сетевых карт, MAC, IP, маски, шлюзы, DNS и DHCP, если Windows предоставила данные через WMI.
- **Папки и принтеры** — имена и UNC-пути общих папок и очередей печати через SMB. WMI дополнительно показывает установленные принтеры, видимые для текущего подключения. Файлы и задания печати не открываются.
- **Общее** — IP, сетевое имя и его источник, MAC из основного сканирования, а при доступном WMI ещё и модель ПК и версия Windows.

Доступ к SMB и WMI зависит от сетевых настроек устройства и прав текущей учётной записи Windows. Карточка показывает, какие источники ответили. [Общие ресурсы SMB](https://learn.microsoft.com/windows/win32/api/lmshare/nf-lmshare-netshareenum) · [Сетевые адаптеры WMI](https://learn.microsoft.com/windows/win32/cimwin32prov/win32-networkadapterconfiguration) · [Принтеры WMI](https://learn.microsoft.com/windows/win32/cimwin32prov/win32-printer)

## Сетевые признаки

Режим по умолчанию проверяет доступность TCP-портов из выбранного сегмента. Устройства обнаруживаются по ARP, ICMP или успешному TCP-соединению. Открытый порт указывает на возможную службу. Для вывода об установленном ПО нужна отдельная проверка. Если TCP-соединение не установлено, порт может быть закрыт или недоступен из-за сетевой фильтрации.

| Порт TCP | Возможная служба |
| --- | --- |
| 3389 | [RDP](https://learn.microsoft.com/en-us/windows-server/remote/remote-desktop-services/remotepc/change-listening-port) |
| 5900 | [VNC](https://help.realvnc.com/hc/en-us/articles/360002249797-All-About-Direct-Connections) |
| 5931 | [Ammyy Admin, пример прямого подключения](https://www.ammyy.com/ru/admin_manual.html) |
| 5938 | [TeamViewer, входящие LAN-подключения](https://dl.teamviewer.com/docs/en/v15/TeamViewer-Manual-Remote-Control-en.pdf) |
| 7070 | [AnyDesk, прямые подключения](https://support.anydesk.com/docs/settings) |
| 21115 | [RuDesktop, прямые P2P-подключения](https://rudesktop.ru/static/help/html/docs/faq/client.html) |

Для «Ассистента» публичное руководство описывает встроенный поиск в локальной сети в разделе **Администрирование → Поиск устройств в сети**. Постоянный входящий порт клиента в руководстве не указан. Порт ID-сервера относится к соединению с инфраструктурой и не используется как признак на рабочем ПК. [Руководство «Ассистента», раздел 9.3](https://xn--80akicokc0aablc.xn--p1ai/assets/doc/site/User%20Manual.%20Client%20application.pdf)

## Реестр Windows

Для чтения реестра удалённого Windows-ПК необходимы доступ по SMB, доступная служба Remote Registry и права текущей учётной записи Windows. Приложение использует текущие разрешения и не меняет настройки удалённых ПК. [Документация Microsoft по удалённому реестру](https://learn.microsoft.com/en-us/dotnet/api/microsoft.win32.registrykey.openremotebasekey?view=net-10.0)

**Проверен** означает, что приложение прочитало обе ветки установленных программ и доступные загруженные профили. При неполных данных отображается **Частичная проверка**, при отсутствии доступа — **Не проверен**. Портативные программы без записи об установке и программы в незагруженных профилях могут остаться вне отчёта. Компьютеры без ответа и устройства за маршрутизатором в список не попадают.

## Сборка установщика

Понадобятся .NET 10 SDK и NSIS 3.13 с доступным в `PATH` компилятором `makensis.exe`.

```powershell
.\deploy\windows-desktop\Build-Installer.ps1
```

Готовый установщик находится в `artifacts/LAN-Guard-Setup-x64.exe`. Подписать пакет Authenticode можно после сборки сертификатом издателя.
